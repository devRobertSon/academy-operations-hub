# 시스템 구조

## 경계

### 학사 포털

- 주소: `academy.robertson.kr`
- 저장소: `academy-operations-hub`
- Firebase: 새 학사 전용 프로젝트
- 자료: 학생, 수업, 수강 이력, 평가, 진도, 상담, 진단평가, 로드맵

### 급여 포털

- 주소: `payroll.robertson.kr`
- 저장소: `academy-payroll-console`
- Firebase: 기존 급여 전용 프로젝트
- 자료: 선생님 급여, 수업 시수, 공제, 명세서, 영수증

두 포털은 화면 링크만 공유합니다. Firebase 세션과 데이터베이스는 공유하지 않습니다.

## 프런트엔드

GitHub Pages에서 정적 HTML, CSS와 JavaScript를 배포합니다. GitHub Actions는 사용하지 않습니다. Firebase Web SDK가 Google 로그인과 Firestore 접근을 담당합니다.

로컬에서만 `?demo=admin`과 `?demo=teacher` 미리보기를 허용합니다. 배포 도메인에서는 Firebase 설정과 승인이 없으면 업무 화면이 열리지 않습니다.

## 권한

| 역할 | 범위 |
| --- | --- |
| `academic_admin` | 학생·반·배정·학습 기록·가져오기·사용자 관리 |
| `counselor` | 학생 기본 학사정보·입학 상담·진단평가·로드맵 |
| `teacher` | 담당 반과 학생·본인이 작성한 평가와 진도 |

한 사용자는 여러 역할을 가질 수 있습니다. 급여 포털 관리 권한과 학사 포털 관리 권한은 별도로 부여합니다.

## 서버 작업

1차 버전은 에듀오케이 CSV를 브라우저에서 미리보기만 합니다. 저장 확정, 대량 쓰기, 외부 API 자동 동기화와 보고서 생성은 서버 작업이 필요한 단계에서 Cloudflare Worker 또는 별도 백엔드로 분리합니다.

API 키, 서비스 계정, Google Drive 토큰과 에듀오케이 인증정보는 공개 저장소나 브라우저 코드에 넣지 않습니다.

## 단계

1. 저장소·화면·권한·데이터 모델
2. Firebase 연결과 첫 관리자 승인
3. 에듀오케이 실제 파일 열 매핑과 가져오기 확정
4. 학생·반·수강·담당 선생님 이력
5. 평가·진도 입력과 수정 이력
6. 진단평가·상담 원서·PDF 보고서
7. 시간표 제약과 학습 로드맵
8. 공식 API가 제공될 경우 읽기 전용 자동 동기화
